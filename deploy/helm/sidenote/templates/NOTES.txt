Sidenote is installed as release {{ .Release.Name }} in namespace {{ $ns }}.

Open the panel
  The panel has no login and shows your screen, so the server takes connections from inside its own
  pod only. Forward its port to the machine you sit at:

    kubectl --namespace {{ $ns }} port-forward svc/{{ $server }} 8777:{{ .Values.server.service.port }}

  and open http://127.0.0.1:8777 in a browser on that machine. Keep the forward on 127.0.0.1, the
  default: --address 0.0.0.0 would open the panel to your network.

Connect the capture program
  It sends the screen and the sound to ws://127.0.0.1:8777/ingest, its default address. Run the
  port-forward above on the PC with the screen (on Windows, or in WSL on that PC: Windows reaches
  WSL's localhost), then start the program as usual: from the repository,

    ./sidenote capture

  or from the release's sidenote-capture zip, on Windows or on a Linux desktop with X11,

    py -3 capture.py --server ws://127.0.0.1:8777/ingest
    python3 capture.py --server ws://127.0.0.1:8777/ingest

  A port-forward ends when the pod behind it is replaced (an upgrade, a restart). Run it again; the
  capture program and the panel reconnect by themselves.

The local model

  The model-pull Job has put {{ include "sidenote.llm.pullModels" . | fromJsonArray | join ", " }} on the models volume. Its log:

    kubectl --namespace {{ $ns }} logs job/{{ include "sidenote.componentName" (dict "context" . "component" "llm-pull") }}

  No model has been downloaded by this release (llm.pull.enabled is false). Until one is there the
  agent solves everything, if it is signed in. Download the models, tens of GB, with:

    helm upgrade {{ .Release.Name }} oci://ghcr.io/kanggu12/charts/sidenote --version {{ .Chart.Version }} --namespace {{ $ns }} --reuse-values \
      --set llm.pull.enabled=true --timeout 2h
